# Установка Кодекс Пульта на своём Mac

Эта инструкция рассчитана на нового пользователя. Нужны собственный Telegram-бот, собственный аккаунт Codex и постоянно работающий Mac. Учётные данные автора репозитория не нужны. Выполняйте шаги по порядку; команды запускайте в Terminal.

## 1. Подготовить компьютер и Codex

Установите Git, Python 3.11 или новее (проверено с 3.13), Node.js с npm и Visual Studio Code. Python можно взять с [python.org](https://www.python.org/downloads/macos/), Node.js — с [nodejs.org](https://nodejs.org/), VS Code — с [code.visualstudio.com](https://code.visualstudio.com/). При первом запуске `git` macOS может предложить установить Command Line Tools.

В VS Code установите расширение Codex от OpenAI (`openai.chatgpt`), откройте панель Codex и войдите в свой аккаунт ChatGPT с доступом к Codex. Откройте любой свой проект, создайте локальную беседу и убедитесь, что обычный запрос с компьютера получает ответ. Это первый обязательный контрольный результат. [Официальная инструкция расширения](https://learn.chatgpt.com/docs/codex/ide).

Если Codex CLI ещё не установлен, установите его через npm (Node.js и npm уже должны быть доступны):

```sh
npm install -g @openai/codex
```

Другие способы — в [официальной инструкции CLI](https://learn.chatgpt.com/docs/codex/cli). Для уже установленного CLI этот шаг пропустите: не переустанавливайте работающую среду. Затем проверьте:

```sh
git --version
python3 --version
node --version
npm --version
codex --version
codex login status
```

Если CLI ещё не авторизован, выполните `codex login` и войдите в тот же аккаунт, что в расширении. Не передавайте токены ChatGPT в Telegram. CLI и расширение должны использовать один CODEX_HOME (по умолчанию `~/.codex`). Для первой установки используйте стандартный каталог; нестандартный CODEX_HOME нужно одинаково настроить и в окружении LaunchAgent, и в VS Code.

Проверено с CLI 0.153.0 и расширением openai.chatgpt 26.930.41038 на macOS Apple Silicon. Это сведения о проверенной среде, а не обещание совместимости всех версий. При ошибке IPC сначала смотрите [диагностику](DEVELOPER_GUIDE.md#совместимость-и-диагностика), не меняйте модель или разрешения ради обхода.

## 2. Скачать проект и подготовить Python

Если GitHub запросит вход, используйте свой аккаунт с доступом к репозиторию.

```sh
mkdir -p "$HOME/Projects"
cd "$HOME/Projects"
git clone https://github.com/jlekc/codex-remote-pult.git
cd codex-remote-pult
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install certifi
```

Основной код использует стандартную библиотеку. certifi нужен для надёжного HTTPS на Python/macOS. Окружение `.venv` остаётся локальным. В следующих шагах работайте из этой папки с активированным окружением; в новой вкладке Terminal снова выполните `cd "$HOME/Projects/codex-remote-pult"` и `source .venv/bin/activate`. Если скачали в другой каталог, используйте свой путь.

## 3. Создать собственного Telegram-бота

1. Откройте официальный [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, задайте имя и свободный username, заканчивающийся на `bot`.
3. Сохраните полученный токен приватно. Не вставляйте его в Git, чат агента или скриншоты.
4. В настройках именно своего бота откройте Mode Settings → Threads Settings.
5. Включите **Threaded Mode** и **Disallow users to create new threads**. Первый переключатель даёт ветки, второй не позволяет Telegram превращать нажатия служебных кнопок в новые ветки. Темы бесед будет создавать сам бот.
6. Откройте своего бота по ссылке `https://t.me/<ваш_username>`, нажмите Start и отправьте `/start`.

Другие специальные режимы BotFather для пульта не нужны. Управление работает только в настроенном личном чате. [Telegram Bot API](https://core.telegram.org/bots/api#user) описывает проверочные поля `has_topics_enabled` и `allows_users_to_create_topics`.

## 4. Сохранить токен и Telegram ID локально

До запуска фонового моста выполните:

```sh
python3 notify.py --setup
```

Введите токен BotFather в скрытом вводе. Программа проверит username бота. Когда попросит, отправьте сообщение своему боту, вернитесь в Terminal и нажмите Enter. Из показанных личных чатов выберите свой числовой chat_id и введите его. Если список пуст, отправьте боту ещё одно сообщение и повторите настройку.

Результат: рядом с кодом создан `credentials.json` с правами 0600 и пришло тестовое уведомление в Telegram. Токен не нужно писать вручную в код или `.env`. Не копируйте чужой credentials.json.

```sh
python3 notify.py --test
```

Второе тестовое уведомление должно прийти даже при выключенном режиме пульта. Оно проверяет Telegram, но ещё не работу с беседой VS Code. Повторный `--setup` выполняйте после остановки моста: два процесса getUpdates одного бота конфликтуют.

## 5. Подключить конечные ответы Codex

Пульт использует пользовательскую настройку `notify` Codex. Она задаётся в `~/.codex/config.toml`, а не в `.codex/config.toml` проекта. [Официальное описание конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference).

Сначала сделайте резервную копию конфигурации, если она существует:

```sh
python3 - <<'PYCODE'
from pathlib import Path
import shutil, time
p = Path.home() / '.codex/config.toml'
p.parent.mkdir(parents=True, exist_ok=True)
if p.exists():
    backup = p.with_name('config.toml.backup-' + str(time.time_ns()))
    shutil.copy2(p, backup)
    backup.chmod(0o600)
    print('Резервная копия создана:', backup)
else:
    p.touch(mode=0o600)
    print('Создан пустой config.toml')
PYCODE
```

Откройте файл в редакторе. Если корневой `notify` уже задан, сохраните его массив команд в локальный `previous-notify.json` рядом с dispatch.py **перед заменой**. Пример формы: `["/абсолютный/путь/python3", "/абсолютный/путь/старого-обработчика.py"]`; используйте прежнюю команду полностью, включая аргументы. Этот файл исключён из Git. dispatch.py вызовет и прежний обработчик, и Telegram.

Если `notify` уже указывает на dispatch.py этой папки, ничего не заменяйте и не записывайте dispatch.py в previous-notify.json: получится рекурсия. При нестандартной конфигурации с hooks сначала попросите агента проверить интеграцию, сохранив действующие обработчики.

Получите строку для своего компьютера (команда только печатает её, не меняет config):

```sh
python3 - <<'PYCODE'
import json, sys
from pathlib import Path
print('notify = ' + json.dumps([sys.executable, str(Path('dispatch.py').resolve())]))
PYCODE
```

Вставьте её как корневую настройку в config.toml **до первого заголовка `[таблица]`**, заменив прежний корневой notify, если он был. Не добавляйте второй ключ notify. Пути должны быть абсолютными; вывод уже учитывает вашу папку и Python из `.venv`.

Проверьте синтаксис TOML, не выводя содержимое:

```sh
python3 - <<'PYCODE'
import tomllib
from pathlib import Path
with (Path.home() / '.codex/config.toml').open('rb') as f:
    data = tomllib.load(f)
assert isinstance(data.get('notify'), list), 'notify должен быть в корне файла'
print('TOML прочитан; корневой notify задан')
PYCODE
```

Перезагрузите окно VS Code через Developer: Reload Window после сохранения config.toml. Обычное обновление Python-кода пульта Reload Window не требует. Не меняйте глобальные sandbox/approvals, модель или аккаунт ради установки пульта.

## 6. Включить фоновый мост

В папке репозитория, с активированным окружением:

```sh
python3 autostart.py install
python3 autostart.py status
```

Ожидаемый результат: `state = running`, PID и уведомление «Мост Codex подключён». LaunchAgent использует выбранный Python, запускается при входе в macOS и пишет логи в `logs/`. Терминал можно закрыть.

Не запускайте одновременно bridge.py вручную. Этот проект устанавливает один LaunchAgent на macOS-пользователя. Не ставьте несколько копий с одним ботом. Если `codex` или `node` доступны только через менеджер версий, их каталоги должны быть доступны в PATH LaunchAgent: см. руководство разработчика.

## 7. Проверить полный цикл на отдельной беседе

1. В VS Code откройте отдельную тестовую беседу без выполняющейся работы.
2. В Telegram отправьте `/start`, нажмите **🔴 Вкл/Выкл**: кружок должен стать зелёным.
3. В основном чате бота нажмите «Выбрать чат» и выберите тестовую беседу. Для неё бот создаст ветку. В уже привязанной ветке нельзя выбирать другую беседу.
4. В этой ветке отправьте «Ответь только: ПРОВЕРКА». Должен прийти один конечный ответ «ПРОВЕРКА» в ту же ветку.
5. Напишите в той же беседе с компьютера «Ответь только: КОМПЬЮТЕР». В Telegram должны прийти копия запроса с зелёным маркером и конечный ответ с синим. IDE-вкладки в копию не включаются.
6. Нажмите «Выбрать чат» → «⬇️ Вывести следующие 5 ⬇️». Если бесед больше пяти, появится следующий список; предыдущие кнопки останутся. Если бесед пять или меньше, продолжения не будет.
7. Нажмите «Статус» и «Лимиты». Не должно возникать отдельных веток с названиями этих кнопок.

Полный цикл подтверждён только после реального ответа из VS Code. Тест `notify.py --test`, успешный запуск LaunchAgent или открытие URI сами по себе этого не доказывают. Для проверки разрешений/очереди/вопросов используйте отдельную тестовую беседу, не рабочую задачу.

## 8. Ежедневное использование, обновление и удаление

Кнопки, вопросы, файлы и очередь: [USER_GUIDE.md](USER_GUIDE.md). Правила помощи агента: [AGENTS.md](AGENTS.md).

Обновление из папки проекта с активированным окружением:

```sh
git status --short
git pull --ff-only
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
python3 autostart.py restart
python3 autostart.py status
```

Если есть собственные изменения или pull отказался, сначала разберите их; не применяйте reset/clean. Секреты и runtime-файлы Git не обновляет. После переноса папки заново установите LaunchAgent и исправьте абсолютный путь notify. Не удаляйте `.venv`, пока notify и сервис используют её Python.

Для остановки: `python3 autostart.py stop`; для возврата: `python3 autostart.py start`. Для удаления автозапуска: `python3 autostart.py uninstall`. Перед удалением папки верните прежний notify из previous-notify.json (или уберите только своё подключение), перезагрузите VS Code. Токен при необходимости отзовите в BotFather. Uninstall не удаляет историю и локальные файлы.

## Если установка остановилась

| Симптом | Действие |
|---|---|
| Нет `python3`, `node`, `codex` | Завершите шаг 1; проверьте PATH |
| Нет тестового уведомления | Проверьте токен, Start у своего бота, интернет/VPN; повторите шаг 4 |
| getUpdates конфликтует | Остановите другой мост или webhook своего бота; один bot token — один получатель updates |
| HTTPS не проходит | Установите certifi в тот Python, которым запускается мост; TLS-проверку не отключайте |
| Сервис не running | Проверьте `logs/bridge.err.log`, `logs/bridge.out.log` и `server.log`; не публикуйте полные логи |
| Бот пишет, что владелец недоступен | Откройте именно выбранную беседу в панели Codex VS Code |
| IPC version mismatch | Зафиксируйте версии CLI/расширения и дайте агенту DEVELOPER_GUIDE.md |
| Запрос uncertain | Проверьте историю/очередь VS Code до повтора; автоматического повторного запуска нет |
| Лишние ветки от кнопок | В BotFather проверьте оба переключателя из шага 3 |

Секреты остаются на компьютере, но пересланный текст и файлы попадают в ваш Telegram-чат. Для демонстрации установки используйте обезличенную тестовую беседу.
