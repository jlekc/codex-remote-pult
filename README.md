# Кодекс Пульт

Личный Telegram-бот [@codex_remote_pult_bot](https://t.me/codex_remote_pult_bot) для работы с Codex в VS Code на Mac. Пересылает только конечные ответы агента, принимает текст, изображения и файлы, поддерживает очередь, создание бесед, разовые разрешения, вопросы с вариантами и собственным ответом.

## Быстрый старт

Mac включён, не спит и подключён к интернету. VS Code с Codex работает, нужная беседа открыта.

1. Отправьте боту `/start`.
2. Нажмите «🔴 Выключен · включить» и «Выбрать чат».
3. Отправьте промпт; дождитесь запуска из очереди и финального ответа.
4. Для другой беседы ответьте на её уведомление в Telegram.
5. Вернувшись за компьютер, нажмите «🟢 Включён · выключить».

Входящие файлы — до 20 МБ, исходящие — до 50 МБ. Голосовой ввод — диктовка клавиатуры телефона; voice Telegram не расшифровывается. Под ответами с файлами появляются кнопки скачивания и команды /file_ID. На вопросы агента можно отвечать кнопкой варианта или своим текстом.

## Обслуживание

```sh
cd /Users/aleksejkalinicenko/Workspace/10_codex_remote_pult
python3 autostart.py status
python3 autostart.py restart
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Установленный LaunchAgent запускает мост при входе в macOS. Для повторной настройки используйте `python3 notify.py --setup`; для установки автозапуска на новом Mac — `python3 autostart.py install`. При переносе проекта обновите пути LaunchAgent и глобального Codex notify, сохранив предыдущий обработчик. Не запускайте две копии моста.

После клонирования токен и runtime-настройки нужно создать локально; они не хранятся в GitHub. previous-notify.json тоже локальный и необязательный.

Токен находится в credentials.json. Runtime-файлы, входящие вложения и логи не публикуйте. Подробности и текущие ограничения — в руководствах выше.

Временные статусы (07.10.2026): «В очереди» и «Промпт запущен» удаляются

Очередь связывается с thread/turn; IDs двух уведомлений и подтверждение финала
хранятся в SQLite progress_runs/progress_notices/progress_finals. Состояние
переживает restart; быстрый финал до записи статуса тоже обработан.
Ошибки, вопросы, разрешения, подключения и ручной /queue не удаляются.
Удаление через deleteMessages не меняет исходный запрос и ответ агента.
Сбой удаления не повторяет ответ; cleanup повторяется фоновым sweep раз в
30 секунд. Telegram ограничивает удаление возрастом сообщения (до 48 часов),
поэтому для очень долгой задачи статус может остаться. Старые сообщения,
не зарегистрированные этим механизмом, не удаляются автоматически.
