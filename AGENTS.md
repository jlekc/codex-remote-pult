## Начать отсюда

Это личный Telegram-пульт для Codex в VS Code на Mac. Бот: @codex_remote_pult_bot. Рабочая папка проекта — /Users/aleksejkalinicenko/Workspace/10_codex_remote_pult. Пользователь общается по-русски.

Прочитай [DEVELOPER_GUIDE.md](DEVELOPER_GUIDE.md) перед исправлением протокола, очереди или разрешений. Пользовательские сценарии и команда /guide берутся из [USER_GUIDE.md](USER_GUIDE.md). ## Что уже реализовано

- /on и /off; одна динамическая кнопка текущего режима и его смены; справка и /guide.
- Финальные ответы из разных бесед: название, ID и reply-привязка всех частей.
- Отправка промпта тому же владельцу VS Code без копии беседы.
- Список чатов по updated_at desc; новая беседа: «Общий чат» без выбора папки или «Чат в проекте» с выбором папки.
- Диктовка телефона как обычный текст; изображения и документы до 20 МБ.
- Сохраняемая общая очередь 20 задач, пауза/удаление и защита от повтора неопределённого запуска.
- Кнопки разовых command/file/permissions approvals из живых снимков владельца.
- Вопросы request_user_input: кнопки вариантов, «Свой ответ», reply и /answer; несколько ответов передаются одной формой, после restart спрашиваются заново.
- Автоматические кнопки файлов и команды /file_ID из Markdown-ссылок; постоянный реестр downloads в SQLite, sendDocument до 50 МБ.
- Фоновый LaunchAgent и flock одного экземпляра.

Голосовые Telegram не распознавать без новой задачи пользователя: он выбрал диктовку клавиатуры. Не заменять работу с беседой VS Code отдельным облачным агентом или CLI-чатом.

## Важные технические решения

Bridge/Features получают Telegram updates и сохраняют offset до обработки. Read-only app-server читает историю/лимиты; старт и interrupt идут по приватному thread-follower IPC. Сокет локальный, без внешнего порта. Только настроенный личный Telegram-чат может управлять ботом.

UI текстовый input должен содержать text_elements: []. Прежний пропуск приводил к ChatGPT hit a snag. История inProgress временно может выглядеть interrupted: ждать подтверждённого финала. Никогда не делать resume существующей беседы во втором writer: уже был active-writer conflict.

Новый чат создаётся отдельным коротким процессом с legacy history, получает запись о создании через inject_items и сохраняется до передачи VS Code. Простого thread/start было недостаточно. Успешный open URI не доказывает готовность владельца: может ждать разрешения пользователя.

Queue.thread неизменен после приёма. Reply message_id и строка «Чат: ID» важнее выбора. /off сохраняет очередь, /stop ставит её на отдельную паузу. dispatching после сбоя становится uncertain; не переигрывать автоматически. active.queueId позволяет восстановить известный запущенный turn.

Разрешения возвращаются исходному owner/thread/requestId; scope=turn, без постоянного доступа. Исчезнувший запрос, старый snapshot или выключенный режим не должны приводить к разрешению. Владелец и requestId не заменяются на текущий выбранный чат.

## Правила работы

- Не читать и не выводить token/credentials ради диагностики. Не логировать URL с token или весь snapshot.
- Не публиковать state, mode, incoming, deliveries, SQLite и логи. Проверять .gitignore перед коммитом.
- Не редактировать установленное расширение, JSONL историю Codex и пользовательские рабочие файлы ради обхода бага.
- Не менять CODEX_HOME, аккаунт, модель, разрешения и глобальный notify без необходимости задачи. Существующий dispatch сохраняет Computer Use notify.
- Не отправлять тестовый промпт в чат с выполняющейся работой: это уже мешало пользователю. Для живой проверки используй отдельную беседу и безвредную задачу; не выдавай мок-тест за end-to-end результат.
- Не очищать queue/state/receipts для удобства теста. Использовать изолированные временные файлы и mocks.
- Делать изменения по авторизованной задаче без повторных вопросов о рутинных шагах. Не добавлять новые обязательные согласования из предположений.
- Поддерживать документацию: поведение для пользователя в USER_GUIDE, устройство/ограничения в DEVELOPER_GUIDE, короткие устойчивые решения здесь. Не вставлять секреты и текущие токены/ID запросов в документацию.

## Ветки Telegram (09.10.2026)

В BotFather оставьте Threaded Mode включённым и включите
«Disallow users to create new threads». Ветки бесед создаёт бот;
создание тем самим Telegram-пользователем отключено, чтобы нажатия
кнопок управления не превращались в отдельные ветки. Проверка getMe:
has_topics_enabled=true, allows_users_to_create_topics=false.
Уже созданные лишние темы эта настройка не удаляет.
Одна ветка Telegram соответствует одной
беседе Codex; привязка сохраняется в ignored messages.sqlite3. Финалы, копии
десктопных запросов и файлы отправляются в соответствующую ветку.
Для новой беседы нажмите «Новый чат». В ранее созданной пустой ветке
можно нажать «Выбрать чат» для привязки. Неизвестная ветка
не использует выбранный глобально чат. Уже привязанную ветку нельзя переназначить
другой беседе; повторный выбор той же беседы сохраняет привязку.
Создание нового чата из существующей ветки открывает отдельную ветку.
Команды и callback сохраняют контекст ветки; reply из другой беседы отклоняется.
Выключенный Threaded Mode сохраняет обычную доставку для ещё не привязанных бесед.
Очередь подключена к нативной очереди Codex: см. описание ниже.

ветке и исходному owner/expectedTurnId; уже принятые задания не очищаются.
