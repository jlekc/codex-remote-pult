# Инструкции агенту: Кодекс Пульт

Личный Telegram-пульт для Codex в VS Code на macOS. Пользователь говорит по-русски. Рабочая папка — текущий checkout этого репозитория; не используйте пути или username автора как настройки нового пользователя.

## Порядок работы

1. Начните с README.md и SETUP.md. Для настройки человека идите по SETUP.md последовательно; токен он вводит самостоятельно в скрытом Terminal input.
2. Прочитайте USER_GUIDE.md для поведения, DEVELOPER_GUIDE.md перед изменением IPC/очереди/разрешений. План и границы живых проверок — DEVELOPMENT_PLAN.md.
3. Проверьте git status и текущие версии, определите существующий LaunchAgent и notify без вывода секретов. Не переподключайте работающий пульт без задачи.
4. Исправляйте только авторизованный сценарий. Рутинные обратимые шаги не требуют дополнительных согласований. Учетные данные, BotFather-настройки и проверку с телефона, недоступные агенту, поручите пользователю с конкретным ожидаемым результатом.
5. Изолированные тесты, diff review, обновление документов; затем применение кода при необходимости. Не выдавайте mocks/успешный open URI за живой roundtrip.
6. Коммит и пуш — по просьбе пользователя. Перед ними проверить .gitignore, состав staged и отсутствие токенов/локальной истории.

## Установка другого пользователя

Свой bot token и личный chat_id → свой локальный credentials.json через notify.py --setup. Свои аккаунт Codex, проекты и Telegram-ветки. Не копировать credentials/state/SQLite автора. Сначала проверить обычный ответ в VS Code, потом Telegram test, потом полный цикл отдельной беседы.

В BotFather: Threaded Mode включён, Disallow users to create new threads включён. Проверочные поля getMe: has_topics_enabled=true, allows_users_to_create_topics=false. Перед изменением глобального notify сохранить прежнюю команду локально в previous-notify.json; не записывать туда dispatch.py. Устанавливать автозапуск выбранным Python из своего окружения. Не менять глобальную конфигурацию действующего пользователя только ради чтения документации.

## Контракты

- Только настроенный личный Telegram-чат, callback проверяет sender и message.chat.
- Одна ветка ↔ одна беседа. Unknown topic не использует глобальный выбор; нельзя переназначать существующую ветку, reply другой беседы отклоняется.
- Нативная очередь add/list/delete атомарна. Не заменять весь список desktop queue. Не вызывать resume/queue-start/turn-start второго writer существующей беседы: модель исполняет исходный владелец VS Code.
- До dispatch сохранять client ID Telegram-origin; текстовое сравнение не использовать. Outbox.thread неизменен. uncertain не повторять автоматически; проверять историю перед повтором.
- /off и pause ограничивают непереданный outbox. /stop выбранной ветки идёт исходному owner с expectedTurnId, принятая очередь не очищается.
- Snapshot/history связывают client ID с turn. Не считать временное interrupted завершением без подтверждения владельца. Delivery claim не является подтверждением доставки; receipt удаляется после progress_finals.
- UI input обязательно text_elements: []. Не редактировать расширение, JSONL историю и проектные файлы пользователя ради обхода IPC.
- Разрешения только исходным owner/thread/requestId и scope=turn; свежесть snapshot, режим и актуальность запроса обязательны. Никаких автоматических расширений доступа.
- Blocking и async вопросы отправлять обратно в исходную беседу; закрывать после принятия ответа. Конфиденциальные формы только на компьютере.
- Код новых возможностей — в этом checkout. Не менять CODEX_HOME, модель, аккаунт, sandbox/approvals и глобальные hooks без необходимости задачи.

## Актуальный интерфейс

🟢 ВЫ → АГЕНТ — desktop запрос, 🔵 АГЕНТ → ВАМ — конечный ответ. Название беседы, жирная черта, текст; ответ в blockquote, технического подвала нет. Телефонные запросы не эхо, IDE envelope убирается. Commentary/reasoning/tool output и архив при restart/on не пересылать.

Панель: Вкл/Выкл; Выбрать чат / Новый чат; Очередь / Остановить запрос; Статус / Лимиты; Файлы / Помощь. Кружок состояния сохраняется. 20 последних уникальных бесед, по 5, «⬇️ Вывести следующие 5 ⬇️». Компактные заголовки «💬 Чаты 1–5»; предыдущие кнопки меню остаются и не удаляются.

Удаляются только зарегистрированные временные статусы: очередь перед запуском, запуск перед финалом. Сбой удаления не блокирует ответ, cleanup повторяется. Вопросы, ошибки, подключение, ручная очередь и меню выбора этим механизмом не удалять. Файлы выдаются по /files, без отдельного автоматического предложения.

## Проверка и применение

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
git diff --check
python3 autostart.py restart
python3 autostart.py status
```

Команды из checkout с активированным Python. Restart нужен только для изменённого кода. Не запускать вторую bridge.py поверх LaunchAgent. Не переключать сохранённый режим без намерения пользователя. Реальные queue/state/receipts/темы не удалять ради теста.

93 теста и живые проверки перечислены в DEVELOPER_GUIDE.md. Новое окружение всё равно требует ручного roundtrip. Отдельная длительная goal-задача не проверена, подтверждён механизм async-вопроса. Файлы совместимости legacy queue/buttons реально используются; удаление требует отдельной миграции.

Не читать/выводить токены ради диагностики, не логировать Telegram URL с token и целые snapshots. Не коммитить credentials, mode/state, SQLite, previous-notify, incoming, deliveries, logs и .venv. Документы должны описывать текущий код; не дописывайте в конец взаимоисключающие версии решений.
